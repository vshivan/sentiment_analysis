# 🚀 Deployment Guide — Sentilytics

This guide covers deploying Sentilytics to production on Render, Railway, or any PaaS platform.

---

## Prerequisites

- A GitHub account (to push your code)
- A Render/Railway account (or any PaaS that supports Python + PostgreSQL)
- Basic knowledge of environment variables

---

## 🔐 Security Checklist

Before deploying, ensure:

- ✅ `SECRET_KEY` and `JWT_SECRET_KEY` are set to long random strings (not the dev defaults)
- ✅ `ADMIN_PASSWORD` is strong and unique
- ✅ `FRONTEND_URL` is set to your actual frontend domain (not `*`)
- ✅ `DATABASE_URL` points to a PostgreSQL database (not SQLite)
- ✅ `.env` files are in `.gitignore` (never commit secrets)
- ✅ No hardcoded credentials in the codebase

---

## 🎯 Option 1: Deploy to Render (Recommended)

Render provides a one-click deployment via `render.yaml`.

### Step 1: Push to GitHub

```bash
cd sentiment_analysis
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/yourusername/sentilytics.git
git push -u origin main
```

### Step 2: Connect to Render

1. Go to [render.com](https://render.com) and sign in
2. Click **New** → **Blueprint**
3. Connect your GitHub repo
4. Render will detect `render.yaml` and create:
   - Backend (Flask web service)
   - Frontend (static site)
   - PostgreSQL database

### Step 3: Set Environment Variables

In the Render dashboard, go to your **backend** service → Environment:

| Variable | Value | Notes |
|----------|-------|-------|
| `SECRET_KEY` | (auto-generated by Render) | Leave as-is |
| `JWT_SECRET_KEY` | (auto-generated by Render) | Leave as-is |
| `DATABASE_URL` | (auto-set from database) | Leave as-is |
| `ADMIN_USERNAME` | `admin` | Your admin username |
| `ADMIN_EMAIL` | `admin@yourdomain.com` | Your admin email |
| `ADMIN_PASSWORD` | `<strong-password>` | **Set a strong password** |
| `FRONTEND_URL` | `https://sentilytics-frontend.onrender.com` | Your frontend's Render URL |

Go to your **frontend** service → Environment:

| Variable | Value |
|----------|-------|
| `VITE_API_URL` | `https://sentilytics-backend.onrender.com` |

### Step 4: Trigger Redeploy

- Go to each service → **Manual Deploy** → **Deploy latest commit**
- Wait for both services to finish building

### Step 5: Access Your App

- Frontend: `https://sentilytics-frontend.onrender.com`
- Backend API: `https://sentilytics-backend.onrender.com`

Log in with the `ADMIN_USERNAME` and `ADMIN_PASSWORD` you set.

## 🚂 Option 2: Deploy to Railway

### Step 1: Push to GitHub (same as above)

### Step 2: Create Railway Project

1. Go to [railway.app](https://railway.app) and sign in
2. Click **New Project** → **Deploy from GitHub repo**
3. Select your repo

### Step 3: Add Services

Railway doesn't auto-detect `render.yaml`, so you'll create services manually:

#### Backend Service

1. Click **New** → **GitHub Repo** → select your repo
2. Set **Root Directory**: `backend`
3. Set **Start Command**: `gunicorn app:app --workers 4 --bind 0.0.0.0:$PORT --timeout 120`
4. Add a **PostgreSQL** database (Railway will auto-set `DATABASE_URL`)
5. Set environment variables:
   ```
   SECRET_KEY=<generate-random-string>
   JWT_SECRET_KEY=<generate-random-string>
   ADMIN_USERNAME=admin
   ADMIN_EMAIL=admin@yourdomain.com
   ADMIN_PASSWORD=<strong-password>
   FRONTEND_URL=https://your-frontend.railway.app
   ```

#### Frontend Service

1. Click **New** → **GitHub Repo** → select your repo
2. Set **Root Directory**: `frontend`
3. Set **Build Command**: `npm install && npm run build`
4. Set **Start Command**: `npx serve -s dist -l $PORT`
5. Set environment variable:
   ```
   VITE_API_URL=https://your-backend.railway.app
   ```

### Step 4: Deploy

Railway will auto-deploy on every push to `main`.

## 🐳 Option 3: Docker Deployment

### Backend Dockerfile

Create `backend/Dockerfile`:

```dockerfile
FROM python:3.10-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

# Download NLTK data at build time
RUN python -c "import nltk; nltk.download('punkt', quiet=True); nltk.download('averaged_perceptron_tagger', quiet=True)"

EXPOSE 5000

CMD ["gunicorn", "app:app", "--workers", "4", "--bind", "0.0.0.0:5000", "--timeout", "120"]
```

### Frontend Dockerfile

Create `frontend/Dockerfile`:

```dockerfile
FROM node:18-alpine AS build

WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .
ARG VITE_API_URL
ENV VITE_API_URL=$VITE_API_URL
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### docker-compose.yml

```yaml
version: '3.8'

services:
  db:
    image: postgres:15
    environment:
      POSTGRES_DB: sentilytics
      POSTGRES_USER: sentilytics
      POSTGRES_PASSWORD: changeme
    volumes:
      - postgres_data:/var/lib/postgresql/data

  backend:
    build: ./backend
    ports:
      - "5000:5000"
    environment:
      SECRET_KEY: ${SECRET_KEY}
      JWT_SECRET_KEY: ${JWT_SECRET_KEY}
      DATABASE_URL: postgresql://sentilytics:changeme@db:5432/sentilytics
      ADMIN_USERNAME: ${ADMIN_USERNAME}
      ADMIN_EMAIL: ${ADMIN_EMAIL}
      ADMIN_PASSWORD: ${ADMIN_PASSWORD}
      FRONTEND_URL: http://localhost:3000
    depends_on:
      - db

  frontend:
    build:
      context: ./frontend
      args:
        VITE_API_URL: http://localhost:5000
    ports:
      - "3000:80"

volumes:
  postgres_data:
```

Run with:
```bash
docker-compose up --build
```

## 🔧 Environment Variables Reference

### Backend

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `SECRET_KEY` | ✅ Yes | (none) | Flask session secret — must be random |
| `JWT_SECRET_KEY` | ✅ Yes | (none) | JWT signing key — must be random |
| `DATABASE_URL` | No | `sqlite:///senti.db` | PostgreSQL connection string (use PostgreSQL in production) |
| `ADMIN_USERNAME` | No | (none) | Initial admin username (seeded on first run) |
| `ADMIN_EMAIL` | No | (none) | Initial admin email |
| `ADMIN_PASSWORD` | No | (none) | Initial admin password |
| `FRONTEND_URL` | No | `*` | CORS allowed origin (set to your frontend URL) |
| `DEBUG` | No | `false` | Set to `true` only for local dev |
| `PORT` | No | `5000` | Port to bind (PaaS platforms set this automatically) |

### Frontend

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `VITE_API_URL` | No | `/api` | Backend API URL (required in production) |
| `VITE_BACKEND_PROXY` | No | `http://localhost:5000` | Dev proxy target (dev only) |

## 🐛 Troubleshooting

### "SECRET_KEY environment variable is not set"

**Fix**: Set `SECRET_KEY` and `JWT_SECRET_KEY` in your PaaS dashboard or `.env` file.

Generate random keys:
```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

### "No default admin user created"

**Fix**: Set `ADMIN_USERNAME`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD` env vars, then redeploy.

### CORS errors in browser console

**Fix**: Set `FRONTEND_URL` on the backend to your actual frontend domain (not `*`).

### "Database connection failed"

**Fix**: Ensure `DATABASE_URL` is set correctly. For Render/Railway, this is auto-set when you add a PostgreSQL database.

### Frontend shows "Network Error"

**Fix**: Set `VITE_API_URL` on the frontend to your backend's full URL (e.g. `https://backend.onrender.com`).

### NLTK data not found

**Fix**: The app auto-downloads NLTK data on startup. If it fails, check logs and ensure the server has internet access during startup.

## 🛡️ Production Best Practices

- ✅ Use PostgreSQL (not SQLite)
- ✅ Set strong, unique passwords
- ✅ Restrict CORS to your frontend domain
- ✅ Enable HTTPS (Render/Railway do this automatically)
- ✅ Monitor logs for errors
- ✅ Set up database backups (Render/Railway offer this)
- ✅ Use environment variables for all secrets (never hardcode)
- ✅ Keep dependencies updated (`pip list --outdated`, `npm outdated`)
